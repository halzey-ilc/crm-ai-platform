# Оценка моделей и допуск к развёртыванию

Статусы — [STATUS_LEGEND.md](STATUS_LEGEND.md).

## 1. Жизненный цикл модели

```
candidate → evaluated → approved → deployed → monitored → retired
     └──────────── rejected (на любом шаге до deployed)
```

| Переход | Кто или что решает | Статус |
|---|---|---|
| → candidate | Toolkit после успешного эксперимента (manifest + sha256) | ✅ |
| candidate → evaluated | Прогон фиксированных регрессионных наборов, отчёт | 📐 |
| evaluated → approved | **Человек** (владелец задачи) по чек-листу §3 | 📐 |
| approved → deployed | Процедура развёртывания §4 | 📐 |
| deployed → retired | Замена или откат | 📐 |

Успешное обучение **никогда** не означает `approved`.

## 2. Метрики по типам задач

| Задача | Основные метрики | Обязательное сравнение |
|---|---|---|
| Lead scoring | ROC AUC, PR AUC, Brier, калибровка, recall по группам | baseline prior + правило по источнику; временной test |
| Классификация звонков и сообщений | macro-F1, матрица ошибок | **отдельно ru и ky** |
| Структурированное извлечение | точность и полнота по каждому полю, доля выходов с доказательствами в источнике | 100% выходов проходят схему (проверка gateway) |
| Аномалии | precision/recall на размеченных инцидентах | статистический baseline и правила |
| Генерация (резюме, черновики) | оценка людьми по рубрике + автоматическая проверка привязки | версия промпта фиксируется |

Сейчас реализовано: метрики lead scoring в Toolkit ✅; проверка схемы и
привязки выхода в Model Gateway ✅. Остальное 📐.

## 3. Чек-лист допуска (approved)

1. Датасет: версия, provenance, отчёт качества, отсутствие утечек.
2. Модель лучше baseline на временном test с заранее заданным запасом.
3. Качество по группам (источник, язык) не хуже заданного порога.
4. Калибровка приемлема, если модель выдаёт вероятности.
5. Проверка безопасности: модель не выдаёт данные из обучающей выборки, нет межтенантного
   смешения.
6. Задокументированы ограничения и запрещённые применения (например, автоматический отказ
   клиенту — запрещён без отдельного согласования).
7. Формат артефакта совместим с runtime, контрольная сумма совпадает.

## 4. Развёртывание (📐 этап G)

Проверка формата → sha256 → совместимость runtime → функциональные тесты на
эталонных входах → нагрузочный тест → проверка качества на регрессионном наборе
→ проверка безопасности → развёртывание с возможностью отката на предыдущую
версию. Production runtime **не** запускает обучение.

## 5. Регрессии

📐 Для каждого типа задачи — замороженный набор эталонных входов (синтетических
или согласованных) с ожидаемыми свойствами выхода. Прогон обязателен при смене
модели, версии промпта или провайдера.
