# Подключение AI к фронтенду CRM

Документ для того, кто делает экраны CRM. Статусы — [STATUS_LEGEND.md](STATUS_LEGEND.md).

## 1. Главное правило: фронтенд говорит только с бэкендом CRM

```
Браузер / приложение ──(JWT пользователя)──▶ Бэкенд CRM ──(короткий токен, HS256)──▶ AI Platform
                     ◀─── результат ────────               ◀── результат ─────────
```

- Фронтенд **никогда** не обращается к AI Platform напрямую. Ключ подписи токенов есть только
  у бэкенда CRM; права пользователя (видит ли он звонок, сделку, документ) проверяет CRM.
- Все эндпоинты ниже — **эндпоинты CRM** (`/api/v1/ai/...`). Они асинхронные: `POST` создаёт
  запрос (202), результат читается `GET` того же адреса. Пока результата нет — показывать
  ожидание (на CPU 30–60 с, на GPU-сервере 2–15 с).
- О готовом результате CRM создаёт уведомление категории `ai` (его можно отключить).

## 2. Что уже можно подключать ✅ (эндпоинты есть в CRM)

| Экран | Где в интерфейсе | Эндпоинт CRM |
|---|---|---|
| Резюме звонка | карточка звонка: кнопка «Резюме» | `POST/GET /api/v1/ai/calls/{call_id}/summary/` |
| Ежедневная сводка | главная / дашборд менеджера | `POST/GET /api/v1/ai/operations/digest/` (+ автоматически в 06:00) |
| Объяснение KPI | отчёты: «Объяснить» у периода | `POST/GET /api/v1/ai/analytics/kpi-explanation/` `{period, date?, language?}` |
| Черновик ответа клиенту | переписка: «Предложить ответ» | `POST/GET /api/v1/ai/conversations/{id}/reply/` |
| Подготовка к разговору | карточка сделки: «Бриф» | `POST/GET /api/v1/ai/deals/{id}/brief/` |
| Обзор рисков | раздел рисков (owner, admin) | `GET /api/v1/risk/signals/`, `POST/GET /api/v1/ai/risk/review/` |
| Ассистент (действия) | окно ассистента / на сделке | `POST /api/v1/ai/agent/runs/` → `GET .../runs/{id}/` → `POST .../actions/{n}/confirm/` или `/reject/` |

Точные поля — в OpenAPI CRM (`/api/docs/`) и в [API_CONTRACTS.md](API_CONTRACTS.md) (выходы
AI одинаковы: CRM их не переписывает).

## 3. Что готово в AI Platform, но ещё нужно добавить в бэкенд CRM 🟠

| Возможность | AI Platform | Что сделать в CRM |
|---|---|---|
| Ассистент помнит разговор («лучше во вторник») | `agent.plan.v3` | хранить реплики запуска, отправлять до 10 последних; реплики ассистента писать как `Предложено: <инструмент> <значения>` |
| Ассистент назначает встречи и меняет этап сделки | `schedule_meeting`, `move_deal_stage` (v2/v3) | выполнять эти действия после подтверждения (модули встреч и воронки) |
| Расшифровка звонка из записи | `PUT /v1/audio/{ref}` + `call.transcribe.v1` | загружать запись звонка из телефонии, затем запускать резюме по тексту |
| База знаний (вопрос по регламентам) | `/v1/knowledge/files`, `/v1/knowledge/ask` | хранить документы компании, отправлять их с метками доступа (роль, отдел), спрашивать от имени пользователя |
| Поток событий вместо опроса | `GET /v1/jobs/{id}/events` (SSE) | пробросить поток своему фронтенду (EventSource не передаёт `Authorization`) |

## 4. Как показывать результаты

**Общее для всех экранов**
- `generator.is_mock: true` — это **не** анализ ИИ (тестовый режим): показывать плашку «тест».
- `insufficient_data: true` — честное «недостаточно данных»: показывать как нормальное
  состояние («Мало информации для резюме»), не как ошибку.
- Пометка «Создано ИИ, проверьте» у каждого результата; ИИ ошибается.
- Ошибка задачи (`status: failed`) — «Не удалось подготовить, попробуйте позже», без деталей.

**Цитаты и ссылки — главная защита от выдумок**
- Резюме звонка: у каждого пункта `evidence_quote` — дословная фраза из звонка. Показывать
  под пунктом мелким шрифтом/курсивом; по клику — подсветить в тексте звонка.
- Бриф по сделке, риски, сводка: пункты ссылаются на записи (`deal:…`, `activity:…`, `lead:…`)
  — делать их ссылками на эти записи CRM.
- База знаний: каждое утверждение с цитатой и названием документа.

**Ассистент**
- Каждое предложенное действие — карточка с кнопками «Подтвердить» и «Отклонить»; **ничего не
  выполняется без нажатия**. Показывать `reason` («почему») под действием.
- Пустой план (`actions: []`) — «Этого я сделать не могу» (например, «удали все сделки»).
- Дату и время встречи показывать в понятном виде («вт, 3 ноября, 15:00»), а не ISO.

**Черновик ответа клиенту**
- Только вставлять в поле ввода, **никогда не отправлять автоматически**.
- `needs_human: true` (жалоба, отмена) — заметная пометка «Ответьте лично».
- `draft_reply: null` — черновика нет (ИИ не уверен), показать только намерение и срочность.

**Расшифровка звонка** (когда появится в CRM)
- Реплики по времени, с подписью «Менеджер» / «Клиент» (стерео-запись) или без неё (моно).
- Пометка «Машинная расшифровка, возможны ошибки».

**Кыргызский язык**: тексты на кыргызском заметно слабее — до проверки носителем языка
помечать резюме `ky` как «черновой перевод» (см. MODEL_EVALUATION §6).

## 5. Сроки ответа и ожидание

| Где работает модель | Типичное время |
|---|---|
| Ноутбук, CPU (сейчас) | 25–60 с на ответ; расшифровка ~3× длины записи |
| GPU-сервер (T4, измерено) | 2–15 с |

Показывать спиннер с текстом «Готовлю…» и не блокировать остальной экран; результат приходит
уведомлением, если пользователь ушёл со страницы.

## 6. Проверить без фронтенда

- `make playground` в AI Platform — страница для ручной проверки всех типов задач.
- `/api/docs/` в CRM — Swagger для эндпоинтов из §2.
