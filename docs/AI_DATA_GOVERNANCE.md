# Управление данными AI

Статусы — [STATUS_LEGEND.md](STATUS_LEGEND.md). Документ фиксирует правила;
сроки хранения ниже — **предложение**, требующее утверждения владельцем.

## 1. Принципы

1. CRM — источник истины. AI Platform хранит только то, что нужно для AI-задач.
2. Данные одной компании используются только для этой компании. Межтенантное использование
   (например, общая модель) допускается только с документированным основанием, согласием
   компаний и обезличиванием.
3. Внешним поставщикам (LLM API, облачные GPU) данные не передаются без согласованной
   политики. Сейчас не подключён ни один внешний поставщик.
4. Записи звонков и корпоративные документы не обрабатываются, пока не определены
   правовое основание и согласия (в CRM полей согласия нет).
5. Минимизация: в логах нет содержимого, API не возвращает вход задачи.

## 2. Классы данных

| Класс | Где | Доступ | Срок хранения (предложение) | Удаление | Статус |
|---|---|---|---|---|---|
| Документы компании (Knowledge Assistant) | `kb_document`, `kb_passage` | RLS + метки доступа | пока CRM их не удалит (DELETE /v1/knowledge/documents/{ref}) | по запросу CRM, сразу | ✅ |
| Задача целиком: вход (тексты CRM), результат, метаданные | `ai_job`, `ai_job_result` | роль `ai_app` под RLS | `AI_RETENTION_DAYS` (по умолчанию 30) дней после завершения | автоматически каждый час: `ai_purge_finished` | ✅ |
| Аудио | объектное хранилище | по подписанной ссылке, per-tenant префикс | минимально необходимый | удаление объекта и версий | 📐 |
| Датасеты | вне git; далее объектное хранилище | только Training Toolkit | на время эксперимента + аудит | удаление с записью в каталоге | 🟠 версия и provenance ✅ |
| Артефакты моделей | вне git, реестр `$CRMAI_REGISTRY` | — | пока модель не retired + период отката | — | 🟠 реестр и sha256 ✅; очистка retired 📐 |
| Логи | stdout → система логов | эксплуатация | 30 дней | ротация | 🟡 содержимого нет |

### Очистка по сроку хранения ✅

Orchestrator раз в час вызывает `ai_purge_finished(days, limit, run_by)` (миграция 0002).
Функция:
- удаляет только завершённые задачи (`succeeded`, `failed`, `cancelled`) вместе с
  результатами, если они закончились раньше, чем `days` дней назад;
- никогда не трогает задачи в очереди и в работе;
- отказывает при `days < 1`;
- пишет каждый запуск в `ai_retention_run` (когда, сколько, кто — без данных задач).

Права DELETE у роли `ai_app` по-прежнему нет: есть только `EXECUTE` на эту узкую функцию.
`AI_RETENTION_DAYS=0` отключает очистку. Срок 30 дней — предложение, его утверждает
владелец (§5).

CRM хранит свои копии результатов в своей БД, их срок задаёт CRM.

## 2a. Обезличивание ✅ (частично)

`runtimes/redact` (Rust) заменяет перед выгрузкой в обучение или во внешний сервис:
- e-mail, телефоны, номера карт (с проверкой Луна);
- IBAN (mod-97), ПИН KG, ИИН KZ (с контрольной цифрой), паспорта KG.

С ключом получаются стабильные псевдонимы: один клиент — один токен во всех файлах.

**Имена 🟠 (по правилам, без модели), `runtimes/redact/src/names.rs`.** Распознаются:
- около 170 частых русских, кыргызских и казахских имён с падежными окончаниями;
- имена на -бек и -гуль;
- отчества, «уулу» и «кызы»;
- фамилии рядом с именем или отчеством.

Качество измерено только на синтетических предложениях (`tests/names_eval.rs`):

| Набор | Точность | Полнота | Что пропущено |
|---|---|---|---|
| Набор, на котором настраивались правила | 1.00 | 1.00 | — |
| Отложенный набор (на нём не настраивали) | 1.00 | 0.78 | имена вне словаря: «Тилек Осмонов», «Эльвирой» |

**Адреса не распознаются.** Свободный текст после обезличивания всё ещё считается
содержащим персональные данные. 📐 Модель NER на размеченных реальных примерах и
подключение к Training Toolkit при выгрузке реальных данных.

## 3. Удаление по запросу

У роли приложения нет права DELETE (✅). Удаление данных компании или субъекта —
отдельная аудируемая процедура, которую выполняет роль владельца схемы. 📐 Она
должна удалить: входы и результаты задач компании, объекты в хранилище,
датасеты с её данными; модели, обученные на её данных, перевести в `retired`.

## 4. Provenance

Каждый запуск Toolkit записывает в `manifest.json`: версию и sha256 датасета,
вид источника (`synthetic` / `file`), флаг `contains_real_data`, tenant,
параметры, версии библиотек. ✅ Для реальных данных флаг заполняет владелец
данных: Toolkit не может определить его сам и пишет `unknown`.

## 5. Требуют решения

- Утвердить сроки хранения из §2.
- Политика внешних LLM: какие классы данных разрешены, обезличивание, регион, договор.
- Правовое основание обработки звонков и сообщений для AI.
- Разрешена ли межтенантная (общая) модель и на каких условиях.
