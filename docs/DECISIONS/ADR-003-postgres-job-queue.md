# ADR-003: Очередь AI-задач на PostgreSQL

- Статус: принято
- Дата: 2026-10-28

## Проблема

Нужны постановка задач, аренда, повторы, отмена и восстановление после падения
воркера. Требования Foundation — без лишней инфраструктуры.

## Альтернативы

1. RabbitMQ CRM — связывает инфраструктуры двух проектов; статус задачи всё равно нужно
   хранить в БД (двойная запись, нужен outbox).
2. Kafka или Redis Streams — новый тяжёлый компонент без измеренной необходимости.
3. **Таблица `ai_job` + `FOR UPDATE SKIP LOCKED` + аренда с истечением.**

## Решение

Вариант 3. Статус и очередь — одна запись, без двойной записи. Гарантия —
at-least-once; дубликаты результата исключены первичным ключом и проверкой
владения арендой.

## Последствия

- Проверено: конкурентный claim без пересечений, повторный захват после истечения аренды,
  отсутствие второго результата.
- Предел пропускной способности — сотни или тысячи задач в секунду на одном PostgreSQL. Это с
  запасом для AI-задач, каждая из которых длится секунды. Пересмотреть при измеренной нагрузке
  (метрики очереди 📐).
- Polling с интервалом 1 с: задержка старта до 1 с. Позже можно добавить `LISTEN/NOTIFY`.
