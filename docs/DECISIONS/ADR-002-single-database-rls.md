# ADR-002: Одна база метаданных AI с Row-Level Security

- Статус: принято
- Дата: 2026-10-28

## Проблема

CRM изолирует компании отдельными базами. AI Platform хранит задачи и
результаты, и они тоже должны быть изолированы по компаниям.

## Альтернативы

1. **База на компанию, как в CRM** — сильная физическая изоляция, но нужна регистрация и
   провижининг баз, а очередь задач придётся обходить по всем базам.
2. **Одна база, `tenant_id` в каждой строке, фильтры только в коде** — одна забытая проверка
   ведёт к утечке.
3. **Одна база + RLS**: роль приложения не владеет таблицами; политики пускают только к строкам
   с `tenant_id = current_setting('app.tenant_id')`; без настройки строк не видно.

## Решение

Вариант 3. Единственный межтенантный доступ — функция `ai_claim_jobs`
(`SECURITY DEFINER`), которая только арендует задачи. Дальнейшая работа идёт под
tenant задачи. У роли приложения нет DELETE, DDL и BYPASSRLS.

## Последствия

- Изоляция доказывается тестами на уровне БД, а не только кода.
- Данные AI Platform — метаданные и результаты, не бизнес-данные CRM, поэтому общая база
  допустима. Если появятся требования о физическом разделении (регион, отдельный кластер
  крупной компании), схема переносится как есть: `tenant_id` уже в каждой строке.
- Сама база отдельная от баз CRM (свой контейнер локально) и инфраструктуру CRM не меняет.
