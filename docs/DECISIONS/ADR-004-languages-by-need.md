# ADR-004: Языки по необходимости; токены от CRM

- Статус: принято
- Дата: 2026-10-28

## Проблема

Целевой стек включает Go, Rust, C++ и Python. Нужно не использовать язык
ради принципа, а также определить, как AI Platform доверяет вызовам.

## Решение: языки

- **Go** — все сетевые и инфраструктурные сервисы Foundation.
- **Python** — только Training Toolkit (изолированный uv-проект).
- **Rust и C++** установлены (rustc 1.99.1, g++ 15.2), но в Foundation не используются.
  C++ появится, когда будет выбран inference runtime (llama.cpp, ONNX Runtime, CTranslate2
  для faster-whisper) — через готовые движки, без своего. Rust — для потоковой обработки
  аудио, только если профилирование покажет узкое место Go.
- **gRPC/Protobuf** не вводится, пока нет вызова между процессами на разных языках. Внутренний
  контракт сейчас — JSON Schema.

## Решение: доверие к вызовам

CRM аутентифицирует пользователя и проверяет членство, затем выпускает
короткий HS256-токен с одним tenant и scopes. AI Platform не ходит в CRM для
проверки каждого запроса и не принимает tenant из тела.

Альтернативы: проверять пользовательский JWT CRM напрямую (у AI Platform
оказался бы ключ, позволяющий выпускать токены CRM, и ей пришлось бы знать
членство); mTLS без tenant-контекста (не решает задачу изоляции).

## Последствия

- Нужна доработка CRM (выпуск токена) — зафиксировано в CRM_INTEGRATION §3.1.
- HS256 означает общий секрет; переход на асимметричную подпись — улучшение на будущее.
