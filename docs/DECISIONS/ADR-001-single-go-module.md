# ADR-001: Отдельный репозиторий и один Go-модуль

- Статус: принято
- Дата: 2026-10-28

## Проблема

AI Platform должна быть самостоятельным проектом рядом с CRM. Gateway и
Orchestrator разделяют домен задач, контракты и адаптер БД.

## Альтернативы

1. Код внутри репозитория CRM — запрещено условиями, смешивает циклы разработки.
2. Отдельные Go-модули `services/gateway-go`, `services/orchestrator-go` — дублирование
   домена или межмодульные `replace`, несколько версий зависимостей.
3. **Один модуль `crmai` в корне**, бинарники в `services/*`, общие пакеты в `internal/`.

## Решение

Вариант 3. Репозиторий `/home/user/crm-ai-platform`, собственный git, CI, Docker.
Каталоги для Rust, C++ и capabilities не создаются, пока в них нечего класть.

## Последствия

- Одна команда `go test ./...`, одна версия зависимостей.
- Gateway и Orchestrator по-прежнему разные процессы и образы, масштабируются независимо.
- Если сервисы когда-нибудь понадобится разнести по разным командам, модуль можно разделить
  без переписывания: границы проходят по пакетам.
